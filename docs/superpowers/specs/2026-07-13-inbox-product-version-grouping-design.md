# 产品信息收件箱：产品版本归组设计

## 目标

- 将同一供应商、同一产品的 V1、V2、V3 聚合在一个产品组内，并按版本顺序展示。
- 每个版本继续保持独立记录；保存、确认、导入 Category Lab 和删除只作用于当前版本。
- 供应商品名不一致时，系统提供候选建议，但不未经产品经理确认自动模糊合并。
- 人工确认的归组关系保存到腾讯云，换电脑或刷新页面后仍然有效。

## 核心原则

1. 宁可暂时分成两个产品组，也不能把两个不同产品错误合并。
2. 不同供应商的记录永远不自动匹配，也不能在归组弹窗中互相合并。
3. 精确规则可以自动执行；模糊规则只能作为建议。
4. 版本归组不改变原始品名、版本号、状态或任何供应商提交内容。

## 产品身份与自动归组

### 规范化

供应商和品名用于比较时执行以下规范化，但页面仍显示原始文字：

- Unicode NFKC 规范化。
- 去除首尾空格、内部空白和常见中英文标点。
- 英文字母转为小写。
- 不删除口味、规格、原料和产品类型等业务词。

### 精确自动归组

没有人工归组标识的记录，按“规范化供应商 + 规范化品名”自动归组。空格、标点和英文字母大小写差异不会拆成不同产品组。

如果某个已人工确认的产品组中出现过相同的规范化品名，该名称成为该组的已确认别名；同一供应商后续再次使用该别名时，可直接显示在该产品组中。

### 模糊候选建议

模糊建议仅在同一规范化供应商内计算。满足以下任一条件时，可显示“可能属于同一产品”：

- 一个规范化品名完整包含另一个，且较短名称不少于 4 个字符。
- 两个名称的双字字符 Dice 相似度不低于 0.68。

系统最多展示相似度最高的 3 个候选，并说明匹配依据。候选不会自动写入 `product_group_id`，必须由产品经理点击确认。

## 人工归组与纠错

### 合并产品组

- 右侧操作栏增加“调整产品归组”。
- 弹窗优先展示同一供应商的模糊候选，也允许搜索该供应商的其他产品组。
- 确认合并时，当前整个产品组与目标产品组写入同一个 `product_group_id`。
- 目标组内已有的所有历史品名成为该组别名。

### 拆分与恢复

- “移出当前版本”会给当前记录建立新的独立 `product_group_id`，避免它因名称相同立即重新并回原组。
- “恢复自动归组”会清除当前人工产品组全部记录的 `product_group_id`，重新按供应商和规范化品名计算。
- 所有合并和拆分动作都需要确认对话框，并在完成后显示 toast。

## 左侧列表

### 产品组层级

第一层显示：

- 产品组名称：取组内最新版本填写的品名。
- 供应商。
- 版本数量。
- 最新提交时间。
- 状态摘要，例如“2 待处理 · 1 已确认”。

第二层显示每个版本：

- 版本号及版本阶段标识。
- 当前状态。
- 提交时间。
- 本版调整点摘要。

产品组可以折叠和展开；当前选中的产品组始终展开。折叠状态只保存在当前浏览器，不写入业务数据。

### 版本排序

- 可解析的 `V数字` 按数字升序排列，例如 V1、V2、V3、V10。
- 版本号相同时按提交时间升序排列。
- 无法解析的版本排在数字版本之后，再按提交时间升序排列。

### 筛选与排序

- 待处理、已确认、已导入、搜索、分类和档期筛选用于决定哪些产品组出现。
- 只要组内任一版本命中筛选，该产品组就会出现；展开后仍显示该组全部版本，未命中的版本弱化显示，保证版本历史不断裂。
- “按提交时间”按组内最新提交时间倒序。
- “按分类”与“按档期”取组内最新一条已填写对应字段的记录作为组排序值。
- 顶部数量继续统计版本记录数量，不改成产品组数量。

## 中间阅读区

- 标题下增加版本切换条，展示当前产品组内全部版本。
- 当前版本使用深色选中态；每个版本同时显示状态和版本阶段。
- 点击版本只切换当前详情，不重新请求数据，也不改变其他版本。
- 供应商提交内容和产品经理补充测试结果保持现有结构。

## 数据与接口

### 数据字段

CloudBase 文档新增可选字段：

```text
product_group_id: string | null
```

CloudBase 文档数据库不需要表结构迁移。没有该字段的历史记录按自动规则即时计算。

### 后端动作

新增管理员动作 `adminSetProductGroup`：

- 输入：记录 ID 数组和目标 `productGroupId`；恢复自动归组时目标值为 `null`。
- 验证管理员权限、记录存在，并且所有记录属于同一规范化供应商。
- 更新所有指定记录的 `product_group_id` 和 `updated_at`。
- 返回更新后的记录；任一失败时前端重新读取列表并显示明确错误，不静默保留错误状态。

普通供应商提交接口不接受 `product_group_id`，供应商无法指定或修改产品归组。

## 兼容性

- 不修改已有供应商记录、图片、产品经理补填结果、处理状态和 Category Lab 导入标识。
- 不改变 V1、V2、V3 的含义；`versionStage` 继续作为独立阶段标识。
- 删除某个版本仍只删除当前记录，不删除产品组内其他版本。
- 导入 Category Lab 仍只导入当前选中的版本。
- 页面 URL 的 `?id=` 继续指向具体版本，刷新后恢复该版本并自动展开所属产品组。

## 验证标准

- 同一供应商、同一规范化品名自动归组；不同供应商不合并。
- “芋泥巴斯克”和“芋泥巴斯克蛋糕”只产生候选提示，不自动合并。
- V1、V2、V3、V10 按数字正确排序，未知版本稳定排在后面。
- 筛选命中任一版本后，组内完整版本历史仍可查看。
- 人工合并刷新后仍有效；移出当前版本和恢复自动归组均可撤销错误关系。
- 当前版本的保存、确认、导入和删除不影响同组其他版本。
- 收件箱现有排序、搜索、版本阶段、图片和 Category Lab 导入功能保持正常。
