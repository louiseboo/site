# 众测产品信息：年份与档期报价总览

日期：2026-09-04
状态：Louise 已确认预览；功能于 2026-09-07 部署至腾讯 CloudBase 正式站点。

## 已确认方向

- 收件箱顶部增加独立入口「众测产品信息」。
- 按「年份 → 档期」分组，快速查看产品名称、供应商和报价。
- 包含进入众测的版本及众测后优化版本。
- 取消「新增报价」及独立报价历史。业务上价格变更跟随配方变更，价格属于具体产品版本，沿用现有版本记录。

## 页面和交互

新入口与待处理、已确认、已导入、全部并列，但不是新的处理状态，不改变记录的确认或导入状态。

打开后使用独立总览区域，只按年份和档期组织，不再嵌套公司或品类分组。年份倒序，档期沿用现有顺序和标准名称。缺少年份或档期的记录明确放入「年份待补充」或「档期待补充」，不猜测归属；同年的 CNY 别名沿用现有归一规则。

桌面列：产品名称｜供应商｜版本 / 阶段｜报价（元，含税含运）。报价右对齐，缺失显示「待报价」，不是 0。

建议的版本展示规则：同一年份、档期、产品身份下，默认一行显示最新的众测相关版本；可展开查看该档期内的其他众测相关版本，每个版本明确显示自己的报价。产品后续进入中试等阶段，不因此隐藏已有众测记录，也不自动用中试版报价替换众测版报价。

手机端将每行改为紧凑信息卡：产品名、供应商、版本与报价清晰分行，避免横向滚动和按钮挤压。查看记录可进入原有详情，不新增报价编辑按钮。

切换入口保留原有筛选上下文；存在未保存修改时沿用现有草稿保护，不静默丢弃修改。总览只读取已保存数据。

## 记录范围与价格归属

- 众测相关记录：本轮结论为「通过且进入众测」，或测试场景明确为「众测后优化」。只标记优化但缺少前序众测记录的数据也展示其实际场景，不伪造前序版本。
- 不依赖待处理 / 已确认 / 已导入标签筛选：符合上述范围的记录均可查看，且维持既有内部访问权限。
- 产品身份复用现有显式产品组及供应商、产品名称匹配规则，不将不同供应商的同名产品合并。
- 先按各条记录实际年份、档期分区，再按产品身份汇总；不使用某产品最新档期覆盖旧记录的档期。
- 版本排序复用现有版本号、时间及记录 ID 的确定性顺序。
- 每行价格直接读取该版本的 `quote_rmb`。新版没有报价时必须显示「待报价」，不能继承旧版本价格。
- 没有符合条件的记录时显示明确空态；加载或读取失败时给出重试提示，不把错误显示为无产品。

## 实现边界

基于现有 `supplier-submissions-admin.html` 的记录集合、产品身份和档期工具函数构建只读视图，新增独立的范围筛选、分组及渲染函数，避免改变原有收件箱分组路径。

复用现有产品详情及报价字段。不新增报价表、报价写入接口、单独报价弹窗、价格自动继承或降本百分比。保持现有内部权限与公开供应商字段隔离，不向供应商公开内部报价。

本功能不改造现有产品版本创建流程，也不追加「修改价格时必须新建版本」的强制校验；此处仅取消新总览里的独立报价维护功能。

## 验收

1. 顶部入口存在，原有四个入口及其计数、处理动作正常。
2. 同名档期跨年份分开；同年 CNY 标准名和旧别名合并；缺失归属明确展示。
3. 众测与众测后优化记录可见，其他无关版本不混入报价总览。
4. 最新众测相关版本默认可见，展开可比较旧版本；新版本缺价不挪用旧报价。
5. 同名不同供应商不混合；显式产品组归属与现有详情一致。
6. 进入中试后仍能查询原众测及众测后优化版本的价格。
7. 原详情可访问，切换不丢失草稿；无新增报价入口或写入行为。
8. 桌面列对齐；手机端可读、可点击，无横向溢出；内部报价不会进入公开供应商响应。
