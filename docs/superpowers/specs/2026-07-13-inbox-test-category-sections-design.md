# Codex 生成的收件箱测试类别分区设计

## 目标

产品信息收件箱在“待处理”和“已确认”视图中，按测试类别分成“档期测试”和“新品提案”两个清晰区块，减少手动切换排序。

## 分类规则

- `test_category = 档期测试`：进入“档期测试”区。
- `test_category = 新品提案`：进入“新品提案”区。
- 空值或历史异常值：进入“未分类”区并排在最后，避免记录丢失。
- 不修改供应商表单字段、不迁移历史数据，也不新增数据库字段。

## 排序规则

- 区块顺序固定为：档期测试、新品提案、未分类。
- 待处理：每个区块内部默认按提交时间倒序；不强制按档期排序，因为产品经理通常尚未补充档期。
- 已确认：档期测试区按 `CAMPAIGN_OPTIONS` 对应的上市先后顺序排列；未选择档期或无法匹配的档期排在该区末尾，再按提交时间倒序。
- 已确认：新品提案区按提交时间倒序。
- 全部、已导入 Category Lab：保持现有列表与排序逻辑，不额外增加类别区块。

## 现有排序控件

- 顶部排序下拉框继续保留。
- 在待处理视图中，它只改变各类别区块内部的次级排序。
- 在已确认视图中，“档期测试”区始终以档期上市先后为最高优先级；其他区块继续响应现有排序选项。

## 展示与交互

- 每个类别区块显示标题和当前记录数。
- 产品组原有的展开、收起、版本切换、编辑、确认、导入和归组功能保持不变。
- 搜索只显示命中的类别区块，但仍保留该区块内命中产品的当前状态版本。

## 验证

- 待处理记录能正确进入档期测试、新品提案和未分类区，区内按提交时间排列。
- 已确认档期测试按 `CAMPAIGN_OPTIONS` 上市顺序排列，缺失档期排在末尾。
- 已确认新品提案按提交时间排列。
- 全部和已导入视图不新增区块。
- 展开收起、版本归组和状态 Tab 过滤回归通过。
